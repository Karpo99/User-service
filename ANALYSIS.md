# Codebase Analysis

## 1. Architecture Overview
- **REST API surface** – `UserController` exposes registration, login, refresh, logout, ping, and authentication endpoints under `/users`, wiring each action to dedicated services for separation of concerns.【F:src/main/java/com/userservice/controller/UserController.java†L29-L103】
- **Authentication pipeline** – `SecurityConfig` installs a stateless filter chain with a custom bearer filter that validates JWTs, checks invalidation, and seeds the security context for downstream handlers.【F:src/main/java/com/userservice/config/SecurityConfig.java†L35-L70】【F:src/main/java/com/userservice/filter/CustomBearerAuthFilter.java†L19-L49】
- **Token management** – `TokenServiceImpl` builds RSA-signed access/refresh token pairs, reuses refresh tokens during renewal, and exposes helpers for verification and claim extraction.【F:src/main/java/com/userservice/service/impl/TokenServiceImpl.java†L39-L201】
- **User lifecycle** – Registration hashes passwords and assigns roles, login validates credentials before token issuance, refresh enforces active status, and logout invalidates token IDs via `InvalidTokenService` persistence.【F:src/main/java/com/userservice/service/impl/UserRegisterServiceImpl.java†L25-L64】【F:src/main/java/com/userservice/service/impl/UserLoginServiceImpl.java†L25-L42】【F:src/main/java/com/userservice/service/impl/RefreshTokenServiceImpl.java†L24-L58】【F:src/main/java/com/userservice/service/impl/UserLogoutServiceImpl.java†L19-L40】
- **Data model** – `UserEntity` collects JWT claims from persisted state, while `InvalidTokenEntity` stores token IDs marked as unusable for subsequent checks.【F:src/main/java/com/userservice/model/entity/UserEntity.java†L31-L65】【F:src/main/java/com/userservice/model/entity/InvalidTokenEntity.java†L21-L26】

## 2. Strengths
- **Layered responsibilities** – Dedicated services per use case keep controller logic lean and enable targeted testing/mocking.【F:src/main/java/com/userservice/controller/UserController.java†L42-L83】
- **Consistent validation and logging** – Request DTOs apply Jakarta validation annotations, and service methods provide structured logs around key steps, easing observability.【F:src/main/java/com/userservice/model/dto/request/UserRegisterRequest.java†L18-L27】【F:src/main/java/com/userservice/service/impl/RefreshTokenServiceImpl.java†L25-L58】
- **JWT hygiene** – Tokens are signed with asymmetric keys, incorporate typed claims, and authentication derives granted authorities from stored user type for role-based access later in the pipeline.【F:src/main/java/com/userservice/service/impl/TokenServiceImpl.java†L50-L146】【F:src/main/java/com/userservice/model/enums/TokenClaims.java†L8-L19】

## 3. Risks & Issues
- **Invalid token lookup bug** – `InvalidTokenRepository.findInvalidTokenEntityById` queries by primary key instead of `tokenId`, so duplicate invalidation checks always miss unless the generated UUID matches the JWT ID, rendering revocation ineffective.【F:src/main/java/com/userservice/repository/InvalidTokenRepository.java†L7-L9】【F:src/main/java/com/userservice/service/impl/InvalidTokenServiceImpl.java†L29-L37】
- **Exception handling gaps** – The `RuntimeException` handler returns `404` for any runtime failure, masking root causes, and the `UserStatusNotValidException` handler receives the wrong parameter type, so those exceptions fall back to the generic handler.【F:src/main/java/com/userservice/exception/handler/GlobalExceptionHandler.java†L49-L113】
- **Over-permissive security** – All `POST /users/**` routes are publicly accessible, allowing unauthenticated logout or other future POST endpoints, and CORS accepts any origin, method, or header without restriction.【F:src/main/java/com/userservice/config/SecurityConfig.java†L40-L64】
- **Hard-coded secrets/config** – Token lifetimes and RSA keys are hardwired via enum defaults instead of property binding, preventing environment-specific configuration and complicating key rotation.【F:src/main/java/com/userservice/config/TokenConfigurationParameter.java†L19-L31】【F:src/main/java/com/userservice/model/enums/ConfigurationParameter.java†L8-L55】
- **Token parsing duplication** – `CustomBearerAuthFilter` and services repeatedly re-parse the same JWT for ID, payload, and authentication, increasing CPU cost; caching parsed claims per request would reduce overhead.【F:src/main/java/com/userservice/filter/CustomBearerAuthFilter.java†L31-L48】【F:src/main/java/com/userservice/service/impl/TokenServiceImpl.java†L117-L201】
- **Missing automated tests** – `src/test` contains no test classes, leaving critical token logic and business flows uncovered.【F:src/test†L1-L1】

## 4. Recommendations
1. **Fix invalidation persistence** – Rename the repository query to `findByTokenId` (or add a method) and update usages so invalidated tokens are detected before issuing or authenticating sessions.【F:src/main/java/com/userservice/repository/InvalidTokenRepository.java†L7-L9】
2. **Harden exception mapping** – Remove or narrow the blanket runtime handler and ensure each exception method matches its parameter to avoid leaking unhandled errors to clients.【F:src/main/java/com/userservice/exception/handler/GlobalExceptionHandler.java†L49-L113】
3. **Tighten security posture** – Require authentication for sensitive POST routes (e.g., logout), and replace permissive CORS settings with explicit origin/method allow-lists appropriate for deployment.【F:src/main/java/com/userservice/config/SecurityConfig.java†L40-L64】
4. **Externalize auth config** – Inject key material and TTLs through `application.yml` or a secrets vault so environments can rotate keys without code changes and avoid committing private keys to source control.【F:src/main/java/com/userservice/config/TokenConfigurationParameter.java†L19-L31】【F:src/main/java/com/userservice/model/enums/ConfigurationParameter.java†L8-L55】
5. **Optimize token parsing** – Return composite results (claims + authentication) from `TokenService` to eliminate redundant parsing during logout and filter execution, or memoize parsed claims per request lifecycle.【F:src/main/java/com/userservice/filter/CustomBearerAuthFilter.java†L31-L48】【F:src/main/java/com/userservice/service/impl/UserLogoutServiceImpl.java†L23-L39】
6. **Add regression tests** – Introduce unit tests for token issuance/validation and integration tests covering controller flows to detect regressions such as invalid token persistence or exception mapping problems.【F:src/test†L1-L1】
